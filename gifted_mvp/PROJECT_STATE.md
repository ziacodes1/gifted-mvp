# Gifted MVP — Project State

## Current Architecture
- Modular monolith. Backend: Django 5.2 + DRF + PostgreSQL + JWT. Frontend: React 19 + TS + Vite + Tailwind 3 + React Router 7 + TanStack Query.
- Backend: `backend/config` (settings/urls), `backend/apps/*` (domains), `backend/common/*` (permissions, pagination, exceptions), `backend/apps/ai` (provider-agnostic AI: profile synthesis + next step, persisted).
- Frontend: `src/app` (router+providers), `src/api` (axios client+auth), `src/i18n` (en/uz/ru), `src/features/{auth,assessment}`, `src/layouts`, `src/components`, `src/pages/{public,student,parent,admin}`.
- API key stays backend-only. AI flow will be React → Django API → ai.services → provider.

## Completed (Foundation)
- Custom User model (email login, roles STUDENT/PARENT/ADMIN), managers, admin.
- Auth: register / login / refresh / me (JWT, SimpleJWT). Health endpoint.
- Role-based permission classes, default pagination 20, uniform error envelope.
- Frontend: API client w/ transparent token refresh, AuthContext + RequireAuth role guard, 4 layouts, design tokens, official logo wired.

- `GET assessment-sessions/{id}/` returns ALL questions + a `responses` map (not a server-side "current question" pointer) — frontend owns pagination locally; this is what makes refresh-mid-assessment restore trivial and robust.
- Frontend: real `DashboardPage` (status-aware CTA: Start/Continue/View Profile, My Journey strip, Passport teaser), real `AssessmentPage` (`/app/assessment` — one question at a time, `QuestionRenderer` dispatches on `question.type` so new types don't need new pages, Back/Next, progress bar, refresh-restore), real `AssessmentResultPage` (`/app/assessment/result` — "Your emerging profile", signal rings, confidence wording, neutral non-deterministic language, "Build My Gifted Passport" CTA).

Backend-only: ownership isolation, idempotent re-complete guard (400), `tsc`/`vite build` clean, `manage.py check` + `makemigrations --check` clean.

## Completed (Phase 3 — Signals → AI Profile Synthesis → Next Step)
- **Provider abstraction** (`apps/ai/services/provider.py`): `LLMProvider.generate_structured(system, prompt, schema) -> dict`, raises `ProviderError`. `StubProvider` (default, always defers to fallback) and `AnthropicProvider` (official `anthropic` SDK, JSON-schema structured output via `output_config.format`, `effort` from env, server-side refusal fallback `fallbacks="default"`, timeout 30s, 1 retry). SDK errors are mapped to short codes; nothing provider-specific leaks outside this file. Config: `AI_PROVIDER` (stub|anthropic), `AI_API_KEY`, `AI_MODEL` (empty → `claude-opus-5`), `AI_EFFORT` (default `low`), `AI_TIMEOUT_SECONDS`.
- **Synthesis** (`apps/ai/services/profile_synthesis.py`): ONE model call returns `{profile, next_step}`. Input is compact JSON only: assessment title, questions answered, all 5 interest signals (score/confidence/evidence_count; zero-evidence ones included so gaps are visible). Scores are re-derived server-side with `score_session(session)` — never taken from the client, never produced by the LLM. No raw answers, question bank, or personal data sent.
- **Validation**: pydantic `ProfileInsight` (extra=forbid, length limits) + forbidden-phrase regex ("you should become", "you are definitely", …) + `signals_used` filtered to known keys. Any failure → fallback.
- **Fallback**: deterministic `build_fallback()` from strongest signals (headline, summary, strengths, gaps, per-signal next-step activity). Logged at INFO/WARNING; no raw errors in responses.
- **Persistence**: `AIInsight` (learner, session, generation_type, input_version=`s1-p1`, source AI|FALLBACK, provider, model, result JSON, timestamps), unique per (session, type, version). Get-or-create runs under `select_for_update` on the session row → concurrent clicks wait and reuse (verified: 5 parallel POSTs → 1 provider call, 1 row). AI rows are final; FALLBACK rows retry AI after a 10-min cooldown and upgrade in place. Bump `PROMPT_VERSION`/`SCORING_VERSION` to invalidate.
- **API**: `POST /api/v1/ai/profile-synthesis/` body `{session_id?}` (omitted → latest completed). `IsStudent`; not-owned → 404, not completed → 400. Returns `{session_id, source, profile, next_step, generated_at}`.
- **Frontend**: `/app/assessment/result` keeps signal rings (labelled "calculated by rules, not AI") and fetches the insight via TanStack Query (`["profile-insight", sessionId|"latest"]`, staleTime ∞). Reference layout: Overall insight (headline, summary, uncertainty) + Your next step (activity type, reason, "Based on" signal chips, what it clarifies, confidence note) in one card; Emerging strengths + Worth exploring further below; "AI-assisted insight" / "Signal-based insight" badge; "Build My Gifted Passport" CTA. Loading = rotating copy ("Connecting the signals…" etc.) + skeleton, no percentages. Network failure → previous static insight.
- **Verified**: 8 backend tests (AI success + reuse, provider error, stub, bad schema, unsafe language, fallback→AI upgrade, ownership/role/anon, incomplete session). Live browser run: login → assessment → complete → fallback profile (stub); then `AnthropicProvider` against a local mock Messages API → AI profile rendered, reload reused persisted row (121 ms, no new call); unreachable provider → FALLBACK 200 with no leaked details; other student → 404. `manage.py check`, `makemigrations --check`, `tsc`, `vite build` clean. **Not yet run against the real Anthropic API (no key on this machine).**

## Completed (Phase 4 — Gifted Passport v1)
- **Architecture** (`apps/passports`): `Passport` is a thin aggregate (learner 1:1, status EMPTY|EMERGING|GROWING, `version`, `source_session`, timestamps; `passport_number` = `GP-<year>-<id>`). Signal scores are NOT copied — read from `LearnerSignal`; interpretation read from the persisted `AIInsight`. No PassportSignal table (would only duplicate LearnerSignal).
- **Service** (`apps/passports/services`): `sync_passport(learner, session?)` get-or-creates and moves status to what evidence supports; bumps `version` only when a new completed session is reflected. Called from `assessment-sessions/{id}/complete/` and on every read. `build_passport(learner)` = one read model; no aggregation in views.
- **Trust**: scores only from `LearnerSignal`; AI text only from saved `AIInsight` (`get_saved_profile_insight`, read-only); if none, `build_fallback()` is derived on the fly (not persisted). **Opening the Passport never calls an LLM** (test patches provider to raise). No provider/model/version exposed — only `insight_source` AI|FALLBACK for the provenance label. Evidence = real counts (assessment responses of latest completed session); missions/experiences are 0 until those exist. GROWING reserved, never set.
- **API**: `GET /api/v1/passport/` (IsStudent, always the caller's own). Returns `learner{display_name, first_name, member_since}`, `passport_number`, `version`, `status`, `journey[5 stages, only Discover earnable]`, `headline`, `summary`, `insight_source`, `signals[]`, `emerging_strengths`, `exploration_gaps`, `uncertainty_notes`, `suggested_explorations`, `next_step{…, signals_used[{key,label}]}`, `evidence_summary{total, assessment, missions, experiences}`, `message`, `updated_at`. Constant 11 queries worst case (fallback path), no N+1.
- **Frontend** `/app/passport` (`pages/student/PassportPage.tsx`, components in `features/passport/`: `PassportHero`, `WaveSurface`, `PassportBook`, `JourneyProgress`, `EvidenceSummary`, `SignalCard`/`SignalStrength`, `EmergingStrengthCard`, `ExplorationGapCard`, `NextStepCard`, `EvolvingMessage`, `SectionHeader`/`SourceTag`). "Calculated signals" vs "AI interpretation / Signal-based interpretation" tags keep scores visually separate from AI. Next-step CTA "Explore this next" is disabled with a "Soon" tag (missions not built). EMPTY → "Your Gifted Passport starts with discovery." + Start Assessment; no fake values.
- **Assets** (`src/assets/passport/`): `gifted_passport_book.webp` (from `assets/passport/gifted_passport_book_cover_3d.png`, resized) and `passport_wave_banner.webp` (from `light_cream_green_gold_wave_banner_v1.png`, cropped to remove its baked-in card frame/shadow). Logo untouched.
- **Nav/Dashboard**: sidebar label "My Passport"; Dashboard teaser reads `GET /passport/` → "Passport not started" / "Your Passport is emerging · Built from N assessment responses" + "View Passport →"; journey strip "Passport" dot from real status. Emerging Profile CTA already routes to `/app/passport`.
- **Verified**: 14 backend tests (6 new: empty, emerging+AI, emerging+fallback read-only, versioning, isolation/roles, query bound). Browser: Flow C (empty → Start Assessment), Flow A (assessment → Emerging Profile → Build My Gifted Passport → Passport), Flow B (fresh login → Dashboard → View Passport), refresh (only `GET /passport/`, no AI call), 390px mobile no horizontal overflow. `check`, `makemigrations --check`, `tsc`, `vite build` clean.

## Completed (Groq provider — primary for the demo)
- **`GroqProvider`** (`apps/ai/services/provider.py`, official `groq` SDK 1.7.0, `from groq import Groq`) behind the same `generate_structured` interface; profile synthesis / parent insight inputs, validation, banned-phrase checks, fallback and persistence unchanged. Anthropic and Gemini providers untouched.
- **Model** `openai/gpt-oss-20b` (default; `AI_MODEL` overrides, and other providers' model names are ignored). **Structured Outputs in strict mode** (`response_format={"type":"json_schema","json_schema":{"strict":true,...}}`): Gifted's schemas already mark every field required with additionalProperties=false. `reasoning_effort=GROQ_REASONING_EFFORT` (default `low`), `include_reasoning=False`, 10 s timeout (`AI_TIMEOUT_SECONDS`), `max_retries=1`.
- **Measured live**: gpt-oss-20b intermittently returns malformed JSON (~1 in 3 profile calls; Groq answers `400 json_validate_failed`, independent of effort; gpt-oss-120b wasn't better and is ~3× slower). So `GroqProvider` retries **once, only on `invalid_output`**; with it, 5/5 spaced live profile calls succeeded at 1.3–1.5 s. Free-tier limit on this key: **8,000 tokens/min** (~2.5k per profile call), so bursts of rehearsals may hit `rate_limited` → fallback; leave ~30 s between full runs.

## Important Decisions
- **Backend runs on port 8001** (8000 occupied by another local project).
- Session detail API returns the full question list + response map rather than a server-tracked "current question" pointer — simpler, and makes refresh/Back trivial. Frontend tracks `currentIndex` locally.
- `POST /assessments/{id}/start/` resumes an IN_PROGRESS session if one exists, else creates a new one — so revisiting after COMPLETED intentionally starts a fresh retake (evolving evidence, not a fixed one-shot test).
- **Found & fixed during live testing:** calling `queryClient.invalidateQueries` on the session query (which has a side-effecting queryFn that calls `start()`) inside `complete()`'s `onSuccess`, before `navigate()` unmounts the page, caused TanStack Query to immediately refetch and silently create a stray duplicate session. Fixed by invalidating the (side-effect-free) `assessments` list query instead. Lesson: never invalidate a query whose `queryFn` has side effects while it may still be mounted.
- Only 5 of RIASEC's 6 interest categories used (Conventional omitted) — not asked for, kept scope tight.

## Known Issues
- Admin page and journey/opportunities student pages are still placeholders.
- Parent view shows the first connected child only (no child switcher yet); the student has no UI to show their connection code yet.
- One attempt per learner per mission (MVP): a completed mission cannot be retaken.
- The AI interpretation still only reads assessment signals; mission evidence is shown beside it until an explicit refresh exists.
- Student sidebar is `hidden md:flex` — there is no mobile nav yet (pre-existing); pages themselves are responsive.
- No LearnerProfile/ParentProfile models yet — register creates User only (ParentChild links users directly).
- Demo student reset to NOT_STARTED after testing (`AssessmentSession`/`LearnerSignal`/`AIInsight`/`Passport`/`Evidence`/`MissionAttempt` cleared) — ready for a clean demo run.
- Live AI path only verified against a mock endpoint; set `AI_PROVIDER=anthropic` + `AI_API_KEY` in `backend/.env` to go live.
- No learner age/grade stored yet, so it is not part of the AI input (the Companion is told they're unknown).
- Groq free tier (8k tokens/min): a Companion turn is ~2–3k tokens, so rapid bursts can hit 429; the Groq SDK then waits and retries (one live turn took 29 s), and a hard failure shows the "try again" state.
- Companion replies come from gpt-oss-20b: good but not flawless (occasional odd word choice in Uzbek/Russian). Conversations can't be renamed or deleted from the UI yet.
- Today's Spark: mini challenges are self-reported (one tap, +5, once a day); spark selection doesn't yet consider multiple missions (only the featured one).
- Engagement: redemptions stay RESERVED (no fulfilment/admin workflow yet); the leaderboard is global (no class/school scoping); demo peers are local demo data only; the Groq free-tier limit still applies to the Companion.
- Diary: no sharing (by design for now), no search/filter by tag, stickers use fixed slots (no free positioning); photo files are served through Django (fine locally, would move to signed/private object storage in production).
